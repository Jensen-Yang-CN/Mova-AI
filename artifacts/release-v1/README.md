# release-v1：端侧决策模型的公开记录

选定模型为**第一轮 Qwen3-0.6B LoRA epoch-3**。它根据环境信号和用户话语输出 `scene`、`intent`、`complexity`、`confidence`、`need_cloud` 与 `slots` 的 JSON；不直接写短信、菜谱或摘要。需要长文本时，产品流程还须调用云端生成接口。

## 随代码提交的产物

| 文件 | 内容 | 来源 |
|---|---|---|
| `metrics.json` | 两轮安全超参数、正式 500 条聚合评测、150 条 AI 复核压力题聚合报告、数据版本摘要；本地有权重时还包含本机计算的 SHA-256 | `python tools/export_public_release.py` 从私有下载目录生成 |
| `LICENSE-Qwen3-0.6B` | Qwen3-0.6B 底座随附的 Apache-2.0 许可证 | 原始模型文件；发布衍生模型时一并保留 |

`metrics.json` **不含**逐条用户话语、教师标签、预测文本、服务器账号、IP、密钥或绝对路径。正式 5500/500 数据与 150 条测试的原文仍在私有数据目录；仓库中的 60/40 行是早期 pilot，不能替代本轮正式数据。两轮训练和误差边界详见 [`docs/06`](../../docs/06-阶段二训练记录.md)、[`docs/10`](../../docs/10-第二轮训练回归审计.md)。

上述权重目前仍在本地私有目录；本仓库提交的是核验信息与复现代码，不应把大文件强行加入普通 Git 历史。GitHub Release 附件须在实际上传并再次校验后单独标记为已发布。

代码仓库的普通 Git 文件有大小限制，因此权重不应直接 `git add`。若单独发布 Q4 模型，需按本地文件重新计算 SHA-256，并附本许可证与模型任务说明。合并、转换、量化和推理命令见 [`docs/11`](../../docs/11-端侧模型合并与GGUF转换.md)。该 GGUF 尚未经 Android 实机验证；服务器 CPU 推理速度不能作为手机速度。

复现公开聚合记录：在私有数据文件已下载到 `scene_ai_server/data/` 对应忽略目录后，从仓库根目录运行：

```bash
python tools/export_public_release.py
```

脚本只将聚合指标与脱敏来源摘要写入本目录。缺少正式报告时会失败，不会生成不完整的“发布结果”。
