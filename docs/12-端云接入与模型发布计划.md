# 从 Q4 GGUF 到完整端云回复：当前状态与接入计划

> 更新于 2026-10-09。目标是完成可演示的移动端原型；已完成事项与待实现事项明确区分。训练和选模结果分别见 [阶段二记录](06-阶段二训练记录.md)、[第二轮审计](10-第二轮训练回归审计.md)；导出命令见 [GGUF 记录](11-端侧模型合并与GGUF转换.md)。

## 1. 已完成的模型链路

1. 教师构造正式 5500 条训练数据与 500 条教师标签 gold；`build_sft.py` 对批次 MD5、ID、契约做校验。
2. 第一轮 Qwen3-0.6B LoRA 训练 3 epoch，正式 gold 上第一轮 epoch-3 为 500/500 契约合法、scene 99.6%、intent 97.0%、`need_cloud` 93.2%、槽位 F1 96.33%。
3. 第二轮加入 204 条 AI 编写规则样本，混合源 5704 条并重新从底座训练 3 epoch。第二轮 epoch-2 在已知压力题上修复部分位置/食物边界，但正式 500 条的 reading 意图与上云判断回退。因此原型保留第一轮 epoch-3，不继续为选模扩展训练轮次。
4. 将第一轮 epoch-3 adapter 与哈希核对后的底座合并，转为 F16 GGUF，再用上游 llama.cpp 做 Q4_K_M 量化。量化文件约 379 MB，服务器 CPU 单条推理正常退出并输出合法决策 JSON。

这些结果分别证明**离线数据、训练、选模和服务器 GGUF 运行**可重复核查。500 条 gold 主要是教师标签；150 条压力题经 AI 复核并已用于分析，均不作为独立人工金标准。单条 GGUF 冒烟不是手机端性能测量。

## 2. 端侧小模型与用户可见结果的区别

端侧模型不是通用聊天模型的替身。它输出的 `scene`、`intent`、`need_cloud` 和槽位属于**内部决策**，不能直接显示成用户要求的短信正文。以“帮我拟一段拒绝帮合伙人搬家的短信”为例：

```text
用户话语与环境信号
  → 端侧 Q4 模型：chat / reply_suggest / goal=拒绝 / need_cloud=true
  → App 校验 JSON 并将原话、目标和语气交给云端聊天接口
  → 云端返回 reply / alternatives / explain
  → App 展示一段可复制的具体短信
```

仓库已有云端 `/chat/reply`、`/chat/context` 接口和聊天结果卡。当前 `MovaRepository` 仍直接调用云端；`Router.decide` 未读取模型输出的 `need_cloud`，`EdgeRuntimeState` 也没有本地 GGUF 的加载状态来源。因此上图的端侧到云端连接**尚未实现**，不能把“服务器 GGUF 推理成功”写成“Android 端云级联成功”。

## 3. 下一阶段只需完成的工程闭环

| 顺序 | 实现事项 | 完成判据 |
|---|---|---|
| 1 | 将 Q4 GGUF 作为独立模型资产放入调试设备可读取的位置，Android 通过 llama.cpp JNI 加载；大文件不进普通 Git 历史 | 真机显示模型加载成功、文件 SHA-256 与发布记录一致 |
| 2 | Android 端复用 `pipeline/contract.py` 的提示与 Qwen3 `enable_thinking=False` 前缀；推理原始输出做 JSON 和契约校验 | 与服务器同一案例得到可解析、合法的决策；失败时走云端兜底 |
| 3 | 用真实本地加载状态更新 `EdgeRuntimeState`；让 `MovaRepository` 消费端侧结果，而不是只依据服务端 `/health` | 技术面板能区分“本地已加载”“端侧判断”“云端生成” |
| 4 | 对 `need_cloud=true` 和必须生成正文的 `chat/reply_suggest` 调用已有云端聊天接口；把原始请求、`goal`、`target_tone` 传入，展示 `reply` | “帮我拟短信”最终出现可复制的短信，而不是只出现路由 JSON |
| 5 | 在一台目标 Android 设备上核对少量典型场景、耗时与内存 | 能演示本地分类、上云生成、模型输出不合法时兜底三条路径 |

`confidence` 尚未做概率校准，不能仅因它输出 0.95 就跳过云端。对短信、长摘要等**需要生成正文**的任务，即使模型错误地给 `need_cloud=false`，当前 0.6B 决策模型也不能代替云端正文生成，应由任务能力边界覆盖这一判断。项目原型先完成可靠的端云功能闭环，不继续增加训练轮次。

## 4. 公开发布边界

- 代码、中文注释、可重跑命令与脱敏聚合指标提交 GitHub；公开指标位于 [`artifacts/release-v1`](../artifacts/release-v1/)。原始正式训练集、gold、逐条预测、含绝对路径的合并清单与原始日志留在私有目录。
- Q4 GGUF 是单独分发的二进制产物；若上传 GitHub，应使用 Release 附件或 Git LFS，不直接作为普通 Git 对象提交。下载后必须核对 SHA-256。
- 模型底座为 Qwen3-0.6B，分发衍生权重时附原始 Apache-2.0 许可证。模型卡需注明它只做端侧结构化判断，且 Android 端侧质量尚未验证。
