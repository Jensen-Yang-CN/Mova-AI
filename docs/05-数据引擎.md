## 1. 七阶段流水线

```bash
cd scene_ai_server
python pipeline/build_dataset.py --limit 150 --budget 120
```

```
① 种子展开        模板 + 词表 → 具体用户输入（确定性，可复现）
        │
② 双教师标注      DeepSeek：确定性标签 + T=1 软标签
        │         Qwen：交叉校验
        ▼
③ 契约校验        contract.validate，不合格直接出局
        │
④ 三信号难度      自一致性 × 教师置信度 × 跨教师分歧
        │
⑤ 近似去重        MinHash + LSH 找候选 → 精确 Jaccard 复核
        │
⑥ 覆盖优化        子模最大化（facility location，1−1/e 保证）
        │
⑦ 配额配比        覆盖保底 → 难度配比（最大余数法）→ 质量补足
        ▼
   distill_dataset.jsonl / eval_gold.jsonl / dataset_report.md
```

每个阶段都有产物落盘、可单独重跑；标注结果缓存在 `data/cache/`，**重跑不会重复消耗 API 额度**。

## 2. 为什么坚持零第三方依赖

除了 API 调用用标准库 `urllib`，**去重、覆盖优化、配比求解全部是自己实现的**，不引入
`sentence-transformers` / `numpy` / `scipy` / `pulp`。

三个理由：

1. **可运行性**：数据引擎要在任何机器上（包括没装 PyTorch 的笔记本）立刻跑起来，而不是先等 2 GB 依赖装完
2. **算法本身就是交付物**：MinHash/LSH、子模贪心、席位分配这些是项目要展示的"算法含量"，用现成库反而把重点藏起来了
3. **可审计**：每一行的行为都能读代码确认，不存在"某个库内部悄悄做了什么"

## 3. 三信号难度评估

### 为什么不问教师"这题难不难"

模型自评难度的校准很差 —— 它给的分数更像"这句话读起来专不专业"，而不是"这个任务对学生有多难"。

### 三个可独立测量的信号

| 信号 | 测量方式 | 越大越难的方向 |
|---|---|---|
| **自一致性** | 同一输入 T=1 采样 k 次，两两计算字段级 Jaccard 一致度 | 一致度低 → 难 |
| **教师置信度** | T=1 生成序列的对数概率的 **10 分位** | 低分位低 → 难 |
| **跨教师分歧** | DeepSeek × Qwen 各自作答，字段级 Jaccard | 分歧大 → 难 |

字段级比对把输出摊平成 `(scene, intent, need_cloud, slot.k=v, ...)` 的集合，
用 Jaccard 计算一致度 —— 这样"槽位少填一个"与"意图判错"都会被计入，而不是只比一个字段。

三个信号加权平均（0.40 / 0.30 / 0.30），缺失信号自动重新归一化权重。

### 信号二是"学生探针损失"的**有意替代**

设计文档 [`02-端侧模型方案.md`](02-端侧模型方案.md) §2.2 定义的信号二是
**student probe loss**（学生 checkpoint 在该样本上的 loss）。学生模型尚未训练，该信号不可得。

因此当前用教师置信度替代。这是**记录在案的替代**，不是偷偷换掉：
`difficulty.estimate()` 预留了 `probe` 回调参数，学生 checkpoint 一旦存在，
只需传入回调即可切换，接口不变。

## 4. 去重：MinHash + LSH

```
字符 3-gram → 128 个通用哈希取最小 → 128 维签名
    → 分 32 带 × 4 行做 LSH 分桶 → 候选对
    → 精确 Jaccard ≥ 0.80 才判定重复
```

**为什么要第 4 步精确复核**：LSH 有假阳性（虽然概率低）。在数据集构建里，
"误删一条不重复的样本"比"漏掉一条重复样本"代价更高，所以最终判定必须回退到精确计算。

`dedup.estimate_false_positive_rate()` 给出漏检率曲线，用于选参数：

| 阈值 | 漏检率（b=32, r=4） |
|---|---|
| 0.80 | ≈ 0.9% |
| 0.90 | ≈ 0.03% |

阈值 0.80 是刻意的：中文短句里"我在厨房，手边有番茄和鸡蛋"与
"我在厨房，手边有番茄和青椒" 的 3-gram Jaccard 约 0.7 —— 
它们**是不同样本**（食材不同），不能删。0.80 正好把它们分开。

## 5. 覆盖度优化：把"选哪些样本"写成子模最大化

### 目标函数

先把候选样本映射到网格 $\mathcal{G}$ = 场景 × 意图 × 难度档，然后定义

$$
F(S) = \sum_{g \in \mathcal{G}} \sqrt{\sum_{i \in S \cap g} q_i}
$$

$q_i$ 是样本质量分。

### 为什么用平方根（而不是直接求和）

如果直接用 $F(S)=\sum q_i$，算法会把样本**全部堆到样本最多的那个格子**里 ——
因为那里总量最大、边际收益最高。平方根让边际收益递减：

$$
\Delta_i = \sqrt{Q_g + q_i} - \sqrt{Q_g}
$$

格子已经很满时，再加一条的收益就变小了，算法于是自动去补空白格子。
这既符合"覆盖"的语义，又保证了 $F$ 是**单调子模**的，贪心有 $(1-1/e) \approx 0.632$ 的近似保证。

### 为什么不必上 lazy greedy

因为边际收益是 O(1) 可算的（只需维护每个格子的质量累加 $Q_g$），
朴素贪心是 $O(N \cdot M)$，万级候选集只需几秒。

**报告里会同时给出随机基线**（`coverage.random_baseline_objective`，200 次随机抽样取均值），
用来证明贪心确实比随机强 —— 这个对照数字是跑出来的，不是写的。

## 6. 配额配比：三阶段填充

| 阶段 | 规则 | 作用 |
|---|---|---|
| **覆盖保底** | 每个网格先取 $\lfloor \text{budget} \cdot \alpha / \|\mathcal{G}\| \rfloor$ 条（该格质量最高者） | 防止长尾格子被整体饿死 |
| **难度配比** | 按"缺口 = 目标数 − 已选数"从大到小，取该难度档质量最高的 | 逼近 简单 30% / 中等 50% / 困难 20% |
| **质量补足** | 预算剩余时全局取质量最高者 | 不浪费预算 |

### 整数名额用最大余数法

`round()` 会让各档名额之和 ≠ 预算。这里用**最大余数法（Hare-Niemeyer）**：
先分整数部分，剩余名额按小数部分从大到小分配，保证总和精确等于预算。

### 关于最优性（写清楚，不吹）

- 阶段一与阶段三在各自可行域内取当前最优，**是最优的**（目标线性、约束是配额）
- 阶段二中"先补缺口最大的档"是**启发式**：各档之间唯一的耦合是"每格总量上限"；
  上限不紧时它等价于最优，上限紧时会与最优有偏差
- 因此模块**同时输出实际达成的配比**，偏差超过 6 个百分点会写进报告的
  `notes` 里，任何偏差都可审计

> 把"没达到目标"如实打出来，比在文档里写一句"配比 30/50/20"诚实得多，
> 也更容易在答辩时被追问而不翻车。

## 7. 软标签与 logit 蒸馏的空间预算

数据集里每条样本都带 `soft_label`：教师逐个生成 token 的 top-K 分布。

这是**让 8 GB 显卡也能做 logit 蒸馏**的关键：训练学生时不需要把教师放进显存，
只要按 batch 读磁盘上的缓存即可。

报告第六节会给出真实测量值与外推到 5 万条的估算，验证
[`02-端侧模型方案.md`](02-端侧模型方案.md) §3.2.2 的可行性论证。

## 8. 实测发现的三个问题（这些是流程真正的价值）

### 问题一：契约枚举用了英文，且 prompt 没列取值 → 合法率 0%

详见 [`04-能力契约.md`](04-能力契约.md) §4。修正后合法率 100%。

### 问题二：`temperature=0` 会摧毁 logprobs

**现象**：DeepSeek 在 `temperature=0` 下返回的 `logprob` 对选中 token 恒为 `0.0`，
候选恒为 `-9999.0` —— 完全不可用。

**原因**：极低温度把输出分布压成 one-hot。这其实在数学上是对的
（$T \to 0$ 时 softmax 退化为指示函数），但对我们毫无用处。

**修正**：标签与软标签**分成两次调用** ——

| 调用 | 温度 | 用途 |
|---|---|---|
| 第一次 | `0.0` | 确定性标签（保证数据集可复现） |
| 第二次 | `1.0` + `top_logprobs` | 软标签 + 置信度信号 |

**副作用（必须记录）**：真正的 KD 应该在**标签序列上**取教师的分布（teacher forcing）。
但对话式 API 不支持"让模型续写指定前缀并返回其对数概率"，
所以当前软标签取自 T=1 的自回归生成，与硬标签序列不严格对齐 —— **这是一个已知偏差**。
若把教师换成自托管的 vLLM/SGLang，可以用 `prompt_logprobs` 精确取到标签序列上的分布，
该偏差即可消除。这也是项目后续接入自托管教师的一个具体动机。

### 问题三：难度分布的稀疏是**语料问题**，不是度量问题

**现象**：第一轮 120 条样本，难度全部落进 easy 档（平均 0.098）。

**排查**：拆开三个信号看分布 —— `teacher_confidence` 全部为 1.000（信号失真）；
修正温度问题后平均难度升到 0.219，出现了 medium 档，但 hard 档仍然为空。

**结论**：前面的种子都是"换个食材名 / 换个文档名"式的**表面变化**，
任务本身毫无歧义，教师当然次次答对 —— 这不是度量不准，是**确实没有难题**。

**修正**：补一组真正的困难样本（约束冲突、信息缺失、跨场景歧义、需要外部知识），
并把种子采样从"全局随机截断"改为**按组轮转**：

> 困难组的模板数远少于"换个食材名"这类组。全局随机截断会让它们
> 以极大概率被整组丢掉，于是 hard 档永远填不满。改成组内打散、组间轮转后，
> 每个 spec 都有代表。

这条经验对任何数据流水线都成立：**稀有类别必须显式保底，不能指望随机采样照顾它。**

```bash
cd scene_ai_server
pip install -r requirements.txt      # 只有在线服务需要；数据引擎其实只需标准库
cp .env.example .env                 # 填入 DEEPSEEK_API_KEY 与 DASHSCOPE_API_KEY
```

## 10. 已知局限

| 局限 | 说明 | 消除方式 |
|---|---|---|
| 评测标签未经人工核验 | 教师标注，因此"拿教师评教师"必然 100%，只能测**标签噪声下限** | 人工抽检 + 修正 |
| 软标签与硬标签序列不对齐 | 对话式 API 无法 teacher-forcing 取分布 | 换自托管 vLLM，用 `prompt_logprobs` |
| 信号二非真正的 student probe loss | 学生未训练 | 训练出 checkpoint 后传入 `probe` 回调 |
| 语料规模小（百级） | 演示流水线，非生产规模 | 扩大种子词表与模板；流水线本身可线性扩展 |
| 中文短句去重仅用字符 n-gram | 同义改写检测不到 | 增加 embedding 语义去重作为第二级（需引入依赖，暂缓） |
