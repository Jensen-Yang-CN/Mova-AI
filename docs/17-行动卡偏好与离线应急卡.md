# 行动卡、主动偏好与离线应急卡

## 1. 通知截图 / 文字 → 行动卡

- 入口：「读懂一页」的“从通知提取待办”“从通知截图提取待办”，或从其他 App 分享一张图片给 Mova。分享后只预览，用户点击“提取分享截图的待办”才上传。
- 文字走 `POST /reading/action-text`；截图走 `POST /reading/action-image`。截图由云端视觉模型转录文字，再由云端文本模型抽取最多五条行动。
- 每条行动包含 `title`、`evidence` 与可空的 `due_at`。后端要求引用片段能在输入文字中找到；截图只能核对 OCR 转录结果，最终仍须用户与原图核对。
- 日期只有在证据片段包含完整年月日、具体时分且与模型给出的带 `+08:00` 时区时间一致时才保留。其余情况显示“原文未给出完整时间”，不开放日历按钮。
- “加入日历”调用 Android 日历插入页面；用户在日历应用中核对并保存，Mova 不直接写日历。

## 2. 用户主动保存的偏好

- 设置页提供“回复偏好”和“忌口食材”两个可清空字段，保存在本机 DataStore，默认均为空。
- 回复偏好只随 `/chat/reply` 请求发送，忌口只随 `/analyze_image` 请求发送；服务端将它们写入对应提示词。
- 偏好只影响云端生成，不更改端侧 0.6B 的训练权重，不对已经保存的结果回溯修改。服务端必须部署本次更新，旧服务端可能忽略新增字段。
- 用户应检查菜谱与自身忌口是否冲突；模型建议不能替代食物过敏的人工确认。

## 3. 断网应急卡

- 在“把话说好”选择“回复对方”，输入短消息后点“断网应急卡（本机）”。需先导入并加载项目的 Q4_K_M GGUF。
- 手机本地模型只识别 `chat/reply_suggest` 与 `goal`，由应用内固定模板提供两句短回复；显式选择的沟通目标优先于模型抽取。
- 本入口不会发云端请求，也不会生成个性化长文本。用户可复制并自行编辑；模型未加载、识别失败或输入不属于回复场景时会给出提示。

## 本轮验证与部署

- 后端行动卡证据与日期校验：`python -m pytest tests/test_action_card.py -q`，2 项通过。
- Android：`:app:compileDebugKotlin --offline` 和 `:app:assembleDebug --offline` 均通过；调试 APK 位于 `SceneAi_App/app/build/outputs/apk/debug/app-debug.apk`。
- 本机没有连接的 Android 设备，本轮未做新功能真机点击验收。使用已有服务端虚拟环境加载新增路由，并以假模型输出直接执行文字/截图行动卡处理函数，各返回 1 条有效待办；尚未调用真实云模型。
- 修改服务端 `app.py`、`mova/prompts.py`、`mova/action_card.py` 后重启服务，再安装新 APK。云端地址和 Key 保持在本地配置中，不写入文档或仓库。
