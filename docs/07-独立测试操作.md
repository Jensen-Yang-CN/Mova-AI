# 独立定向测试：AI 复核 → 正式数据查重 → 对比 epoch-2/3

这份测试用于检查 9 月训练好的 Qwen3-0.6B LoRA 在**新话语和新环境信号**上的表现。`tools/independent_cases.py` 提供 150 条 AI 起草的定向探针。本轮已由 AI 逐条复核并修正审核表；模型预测未参与定标签。它适合做新话语压力测试，**不是独立人工标注金标准**。`tools/independent_eval.py` 还需在服务器对正式数据查重，成功后才会锁定评测文件。工具不调用教师 API，也不重训模型。

正式训练文件在服务器上为 5500 条，旧评测集为 500 条。公开仓库的 `scene_ai_server/data/distill_dataset.jsonl` 与 `eval_gold.jsonl` 只有 60/40 条 pilot，锁定脚本会用行数和 MD5 拒绝它们。

## 1. 覆盖范围

| 问题族 | 条数 | 主要核查 |
|---|---:|---|
| `food_boundary` | 15 | 食物新鲜度、价格、保存问题不误判为烹饪 |
| `location_other` | 20 | 用户自述非枚举当前位置映射为“其他” |
| `location_near_enum` | 15 | 餐厅、交通枢纽、校园、超市、商场的近义位置 |
| `location_destination` | 15 | 目的地不能覆盖用户当前位置 |
| `chat_relation` | 30 | 对话对象与用户的关系枚举 |
| `food_diet` | 10 | 饮食管理与普通做法查询的意图区分 |
| `reading_boundary` | 10 | “概括全文”与“会前提炼要点”的区分 |
| `device_command` | 10 | 设备操作指令不误判为现有能力场景 |
| `file_command` | 10 | 文件操作指令不误判为阅读等场景 |
| `new_context` | 15 | 在新时间、应用和位置组合下跨场景判断 |

共 **150 条、20 种环境信号**。该集是针对已知薄弱点的压力测试，场景分布经过刻意调整，不代表真实流量分布。问题族通过门槛沿用训练交接计划：一般族 ≥90%，负边界族（food_boundary、location_other、location_destination、device_command、file_command）≥95%。15 条族达到 95% 实际意味着全对；门槛只作为定向检查，不能替代真实用户流量指标。

## 2. 本地 AI 复核结果

Windows 主仓库的 `scene_ai_server/data/independent_eval/review.tsv` 已完成本轮 AI 复核：150 条中 95 条通过、55 条修正或补充检查字段。修改包括澄清停车场/学校宿舍当前位置、明确聊天对象关系、区分 `rewrite` 与 `tone_adjust`，以及把有明确依据的 50 条 `need_cloud` 纳入检查（35 条 `true`、15 条 `false`）。与本地正式 500 条旧 gold 和仓库 60 条 pilot 训练数据的表述查重结果是 0 条完全重复、0 条近重复；**完整 5500 条训练数据仍须在服务器检查**。

若移到新机器或该文件不存在，可用下面的命令重新生成**未审核草案**；它不会恢复本轮复核结论，且会拒绝覆盖已存在的审核表，无需安装 PyTorch：

```powershell
cd D:\CodeBase\Mova-AI
python tools/independent_eval.py draft --out scene_ai_server/data/independent_eval/review.tsv
```

审核依据是 `scene_ai_server/pipeline/contract.py` 的 `SCENE_RULES` 和 `SLOTS_BY_SCENE`。`location.place_type` 指当前位置，不是目的地；`chat.relation` 指对话对象。当前表的“备注”明确写有 AI 复核及修正依据。如果今后要报告**人工标注**指标，应由真人重新逐条核对并在锁定时指定 `--reviewer human`，不能直接沿用 AI 复核状态冒充人工审核。

本轮 `need_cloud=true` 仅用于饮食建议、阅读内容提炼和明确要求查询附近场所当前营业/开放信息的案例；`false` 用于可由本地执行的明确时间提醒。设备或文件操作超出当前场景契约，未强行推断其上云标签。50 条标签覆盖多个场景，但仍是定向样本，上云准确率不代表真实流量水平。`complexity` 和 `confidence` 未标注，本轮不报告它们的回归误差或校准指标。

审核表保存为 **UTF-8 制表符分隔 TSV**。不要直接改 JSONL、不要把这些探针并入训练集，也不要先看 epoch-2/3 预测再回头改标签。项目的 `.gitignore` 已排除整个 `scene_ai_server/data/independent_eval/`。

## 3. 在服务器核对数据独立性并锁定 gold

将审核后的 `review.tsv` 上传到服务器项目的 `scene_ai_server/data/independent_eval/`。**本轮改了脚本和样本定义，必须重新上传**最新版 `tools/independent_cases.py` 和 `tools/independent_eval.py` 到服务器项目根目录的 `tools/`；不要只上传 TSV。以下命令从 `scene_ai_server/` 执行：

```bash
cd ~/kube-user/CodeBase_YangJunjie/Mova_AI/scene_ai_server
mkdir -p data/independent_eval
wc -l data/distill_dataset.jsonl data/eval_gold.jsonl
md5sum data/distill_dataset.jsonl data/eval_gold.jsonl

python3 ../tools/independent_eval.py finalize \
  --review data/independent_eval/review.tsv \
  --reviewer ai \
  --train-file data/distill_dataset.jsonl \
  --prior-gold data/eval_gold.jsonl \
  --gold data/independent_eval/gold_v1.jsonl \
  --overlap-report data/independent_eval/overlap.tsv
```

预期正式数据 MD5：训练 `d32b73adbc456212f42eaae2099d93ee`，旧 gold `27a33ffbf5d2dd01d391533cb0443f3c`。任何完全重复的话语都会阻止生成 gold；近重复会写入 `overlap.tsv` 并阻止首次锁定。检查报告后优先改写相近样本；若确认语义任务不同且决定保留，重跑同一命令并加 `--approve-near`。三字片 Jaccard 只是近重复提示，不能证明语义独立。锁定后生成 `gold_v1.jsonl` 和 `gold_v1.manifest.json`（含 SHA-256 与审核来源 `ai`），**不要覆盖这个版本**。

## 4. 顺序运行两个 checkpoint 的预测与评分

在已有的 `mova-train` 环境和 tmux 会话中执行；先用 `nvidia-smi` 查看共享卡余量。脚本逐个加载模型，不应并发运行：

```bash
cd ~/kube-user/CodeBase_YangJunjie/Mova_AI/scene_ai_server
source ~/miniconda3/etc/profile.d/conda.sh
conda activate vllm-v19
source ~/venvs/mova-train/bin/activate
nvidia-smi

BASE_MODEL="$HOME/kube-user/CodeBase_YangJunjie/models/Qwen3-0.6B"
RUN_OUT="data/model_output/qwen3-0.6b-lora-20260929_231853"
GOLD="data/independent_eval/gold_v1.jsonl"

for EPOCH in 2 3; do
  OUT="data/independent_eval/epoch-${EPOCH}"
  python predict_lora.py \
    --base-model "$BASE_MODEL" \
    --adapter "$RUN_OUT/epoch-${EPOCH}" \
    --gold "$GOLD" \
    --output "$OUT/predictions.jsonl" || break
  python ../tools/independent_eval.py score \
    --gold "$GOLD" \
    --predictions "$OUT/predictions.jsonl" \
    --out-dir "$OUT" || break
done
```

每个 checkpoint 应得到 `predictions.jsonl`（150 行）、`report.md`、`report.json` 和 `errors.tsv`。评分脚本会验证 gold 与 manifest 的 SHA-256，拒绝缺失、额外或重复预测 ID；无效契约输出在所有准确率中计错。**不要**拿现有 `pipeline/evaluate.py` 直接评这个 gold：本测试只标注可复核的字段，而旧脚本会对未标注的 `complexity` 给出无意义结果，且其 scene/intent 只以合法输出为分母。

先比较每个问题族的通过率和错误清单，再选 epoch-2/3。若某族系统性失败，按失败样本补种子并增量标注，使用**另一份**新测试集验证修复；不要把本轮已看过的 gold 改成训练目标后继续宣称它是独立测试。若各族通过，再进入 LoRA 合并、GGUF 量化和手机离线验证。

本轮 epoch-2/3 已完成，实测指标、错误归因和修复方向见 [`08-独立定向测试结果.md`](08-独立定向测试结果.md)。
