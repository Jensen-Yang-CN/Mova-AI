# Mova·照应：竞赛叙事与产品方案

更新：2026-10-12。申报方向：自主命题「移动与网络应用开发」。

## 1. 一句话定位

**Mova·照应——面向离家青年的端云协同生活助手。**

主张：**小事有人接住，生活慢慢上手。**

目标用户聚焦第一次离家求学、实习、独立生活的青年。作品从「不知道怎样回复一条消息」切入，把场景理解、沟通目标、可用建议与自主确认连接起来；阅读与做饭作为相邻的日常需求。Mova 是技术项目名，「照应」是面向用户的产品表达。

## 2. 故事开场：离家之后，小事也有重量

> 晚上九点，回到住处。
>
> 手机上，是一条不知道怎样拒绝的求助；桌上，是一份还没看懂的通知；冰箱里，是不知道怎么搭配的几样食材。
>
> 每件事都不大，却都要一个人想明白。
>
> 我们想让手机里的智能，先接住这些小事。

这是用于说明产品的**虚构设计情境**，不是创作者的亲身经历、访谈记录或心理健康研究结论。答辩时可作为场景化开场，不应改写为未经证实的真实故事。

## 3. 为什么设计这个项目

Mova 的设计假设是：很多日常求助并不需要一个复杂的智能体，而需要一个低门槛的起点。用户可能知道自己想拒绝，却不知道怎样表达；知道需要看懂材料，却不知道怎样组织提示词。产品把入口从「选择一个大模型、写好提示词」变成「带来眼前的事，说明自己想达到的目标」。

创意来源可这样表述：

> 我们把目光放在离家生活里的那些小停顿：一句迟迟没有回复的话，一页迟迟没有读完的通知，一顿迟迟没有做出来的饭。它们不是宏大的问题，却决定了一个人今天能不能轻松一点。于是，我们尝试把场景理解放进手机，把需要更多能力的生成交给云端，让用户先把眼前这件事做完。

**启发可以来自日常观察，感染力来自具体情境。** 当前没有记录可核验的用户访谈、规模化使用量或效果提升百分比，申报材料不编造这些数字。

## 4. 最小可演示闭环

主线：**有自己的边界，也能把话说好。**

1. 用户主动粘贴或分享一段消息，并补充背景。
2. 手机上的 Qwen3-0.6B Q4_K_M 识别场景、意图与沟通目标；输出经过契约校验。
3. 用户明确选择「拒绝 / 推迟 / 降低冲突」等目标和表达风格。显式选择优先于模型抽取结果。
4. 云端生成推荐回复、备选表达和简短解释。
5. 用户确认后复制；发送仍由用户完成。结果存入本机历史，方便回看。

可复现输入：

> 帮我拟一段短信回复给合伙人，背景是他想让我帮忙搬家，但我那天要出远门。

这条闭环中的价值不是「替用户答应或拒绝」，而是让用户更容易表达自己的决定。

## 5. 技术为何服务于这个故事

- **端侧理解**：小模型承担有限、明确的结构化任务，约 397 MB 权重可在本机加载；设备断网时仍可试运行场景判断。
- **云端表达**：复杂生成由已有模型服务完成。手机中的决策 JSON 不能直接当短信正文展示。
- **用户控制**：只处理用户主动提交的内容；云端生成会发送这部分内容，不宣称所有数据永不离开手机。系统分享只预填，用户确认后再生成。
- **可检查的失败路径**：模型未加载、输入过长、输出不合法或超时，都提供云端回退与清楚的原因；技术面板记录实际执行阶段。

教师标签 500 条评测中，所选第一轮 epoch-3 的契约合法率为 100%、意图准确率为 97.0%、槽位微平均 F1 为 0.9633。这是离线教师标签评测，不能写成「真实用户准确率 97%」，也不能当作量化后手机全量评测结果。具体来源：`artifacts/release-v1/metrics.json`。

## 6. 视觉与交互方向

视觉概念：**一束可握住的微光**。2026-10-12 升级为珍珠白底色、深海青主视觉和暖珊瑚强调色，首页使用原创玻璃环抱光球背景，四个场景拥有各自的原生装饰；中文字体统一为 Noto Sans SC。素材、生成提示词与当前实机截图见 [竞赛视觉升级](16-竞赛视觉升级.md)。

首页第一屏只回答三个问题：这是什么、能帮我做什么、我现在点哪里。主入口是「先把话说好」，下方提供沟通、阅读、做饭与城市四个场景入口。「运行与技术」保留独立页面，把模型参数与试运行收进展开区域。聊天结果仍展示候选与解释，让视觉服务于可理解、可确认的操作。

## 7. 报名表可用文案

以下对应当前报名表，作品分类选择「自主命题 → 移动与网络应用开发」。

### 作品名称

Mova·照应——面向离家青年的端云协同生活助手

### 作品简介

离家求学、实习与独立生活中，一条难以回复的消息、一份难以抓住重点的通知、一顿不知如何搭配的饭，都可能成为日常的小小为难。Mova·照应面向初次独立生活的青年，将人工智能融入沟通、阅读、做饭和初到陌生城市等具体场景，让求助从眼前的一件小事开始。

作品以“手机先理解、云端给建议、最后由用户决定”为交互原则。沟通辅助形成完整闭环：用户输入消息与背景，选择沟通目标和表达风格；端侧模型识别场景、意图，并辅助提取沟通目标；云端生成推荐回复、备选表达和解释，用户确认后复制使用，并可在本机历史中回看。阅读模块提炼文本、截图与 PDF 的要点；做饭模块依据食材图片提供烹饪建议；“城市初见”提供城市欢迎卡片、美食与景点入口，并支持模拟坐标演示。

项目基于开源 Qwen3-0.6B 完成教师数据构建、LoRA 微调、模型评测、权重合并及 Q4_K_M 量化，将约 397 MB 的模型通过 JNI 接入 Android。作品将场景化交互、端侧理解与云端生成结合起来，帮助用户理清眼前的事，保留自己的表达与决定权。

### 创意来源

创意起点是离家生活中的一些“小停顿”：知道自己想拒绝，却迟迟想不好怎样开口；面对一份长通知，找不到最重要的内容；打开冰箱，却不知道怎样把手边的食材变成一顿饭。项目希望把这些具体需求转化为清楚、容易开始的手机交互，让用户带来问题、说明目标，再选择适合自己的建议。

“城市初见”的灵感来自旅途中常见的城市欢迎短信：一声“欢迎来到这里”，可以成为认识新地方的起点。项目进一步把欢迎信息连接到当地美食、景点与地图入口，让初到陌生城市的人有一个轻松探索的开始。

“照应”既是产品名称，也是设计理念：从一句话、一页材料、一顿饭和一次抵达出发，为独立生活提供具体帮助，让用户逐步形成自己的生活节奏。

### 运行环境

客户端：Android 8.0 及以上，64 位 arm64-v8a / x86_64 架构。已验证的真机演示设备为 OPPO Find X7 Ultra（Snapdragon 8 Gen 3、16 GB 内存、512 GB 存储、Android 16）。端侧 GGUF 模型约 397 MB，通过 App 设置导入；ARM 端侧推理需设备支持 FP16、dotprod 与原子指令。

服务端：Python / FastAPI，连接兼容 OpenAI 协议的模型服务及高德 Web 服务。回复正文、阅读总结、图片食材分析和城市解析 / 推荐需要网络及可访问的后端服务；本机意图判断可离线试运行。

演示方式：Android 手机安装 APK 并导入模型，可通过 USB 连接运行后端服务的电脑完成本地演示。演示材料包含 APK、模型导入与服务配置说明。

## 8. 90 秒演示脚本

| 时段 | 画面与内容 |
|---|---|
| 0–15 秒 | 首页主视觉。讲「离家之后，小事也有重量」，给出未回消息的具体情境 |
| 15–35 秒 | 打开「把话说好」，粘贴消息与背景，选择委婉、拒绝；说明目标由用户决定 |
| 35–60 秒 | 展示本机识别与云端回复。把实际等待保留在实机录像中，不伪装成瞬时生成 |
| 60–75 秒 | 看候选与解释，确认复制，进入本机记录，完成动作闭环 |
| 75–90 秒 | 技术面板展示真实端侧状态和耗时；一句话解释数据、微调、量化与接入的原创工作 |

本轮自建服务已恢复，并完成手机端生成、复制与历史回看。演示时仍需可访问模型服务；断网只能展示本地分类，不能把预置回复伪装成在线生成。

可增加一个 20 秒的「城市初见」演示：在原地回放武汉 → 岳阳的公开模拟点位，展示带模拟标识的欢迎通知与城市卡片。这体现「初到陌生城市的第一份照应」，使用实际高德解析，必须说明坐标输入和时间经过模拟，不作为真实高铁实验宣传。
