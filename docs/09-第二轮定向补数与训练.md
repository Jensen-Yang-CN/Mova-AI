# 第二轮定向补数与 LoRA 对照训练

> 2026-10-08。第一轮 epoch-3 在 150 条 AI 复核的压力测试上全字段通过 110/150；当前位置枚举、实时营业上云、食物边界和饮食管理是主要失误。本轮固定底座、契约与训练参数，只改变训练数据，便于定位增益来源。

## 数据来源与边界

- 原训练源：服务器 `data/distill_dataset.jsonl`，5500 条，MD5 `d32b73adbc456212f42eaae2099d93ee`。
- 原正式评测：服务器 `data/eval_gold.jsonl`，500 条，MD5 `27a33ffbf5d2dd01d391533cb0443f3c`。
- 锁定压力测试：服务器 `data/independent_eval/gold_v1.jsonl`，150 条，SHA-256 `b0d292fd189421d6e762b979540481ca5fb333d4ad585fe335682fa902324fa4`。
- `tools/round2_data.py` 新增 204 条规则明确的 AI 编写样本；来源标记为 `ai_rule_draft`，不冒充教师标注或人工金标准。运行时对三份正式数据做哈希、行数、契约与精确/近重复检查。重合项单独列出并排除。正式 5500 条仅在服务器，因此本地核验不能替代服务器最终检查。
- 混合训练集保留原 5500 条标签，新增样本只占约 3.6%。脚本将原始标签疑似冲突写到 `source_audit.tsv`，只供人工复核，不自动改写。输出目录 `scene_ai_server/data/round2/` 已忽略提交。
- 锁定的 150 条测试样本及其预测不得回填训练。再次在这套测试上选模型，只能作为已知问题的回归检查；宣称泛化提升要另建人工审定的全新留出集。

## 服务器准备

上传主仓库最新的 `tools/round2_data.py`、`.gitignore`、本文件；服务器应已包含 `tools/independent_eval.py`、`tools/independent_cases.py`，以及上述三份正式 JSONL。不要上传本地跟踪的 60/40 条 pilot 覆盖正式数据。

建议先在服务器创建新的 tmux 会话：`tmux new -s mova-round2`。下面所有命令在该会话的同一个 shell 中依次运行。


先逐条看 `new_train.jsonl` 的新标签和 `source_audit.tsv` 的疑点。如果原数据有明显错标，应先决定是否修正原训练源并另存版本，不能让互相矛盾的标签直接参与对照训练。`excluded.tsv` 记录被自动排除的泄漏风险样本；不要把它们重新加回。

## 构建与冒烟

```bash
cd ~/kube-user/CodeBase_YangJunjie/Mova_AI/scene_ai_server
MIX_MD5="$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1],encoding="utf-8"))["mixed_train_md5"])' "$ROUND2/manifest.json")"
NEW_MD5="$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1],encoding="utf-8"))["new_train_md5"])' "$ROUND2/manifest.json")"
python3 build_sft.py \
  --input "$ROUND2/mixed_train.jsonl" \
  --output "$ROUND2/sft_train.jsonl" \
  --expected-md5 "$MIX_MD5"
python3 build_sft.py \
  --input "$ROUND2/new_train.jsonl" \
  --output "$ROUND2/sft_new.jsonl" \
  --expected-md5 "$NEW_MD5"

BASE_MODEL="$HOME/kube-user/CodeBase_YangJunjie/models/Qwen3-0.6B"
RUN_ID="$(date +%Y%m%d_%H%M%S)"
SMOKE_OUT="data/model_output/round2-smoke-${RUN_ID}"
mkdir -p data/train_logs
python3 train_lora.py \
  --base-model "$BASE_MODEL" \
  --train-file "$ROUND2/sft_new.jsonl" \
  --limit 50 --epochs 1 \
  --memory-fraction 0.17 \
  --output-dir "$SMOKE_OUT" \
  2>&1 | tee "data/train_logs/round2-smoke-${RUN_ID}.log"
test "${PIPESTATUS[0]}" -eq 0 || { echo '冒烟训练失败，停止'; exit 1; }
```

冒烟测试取**新增样本**前 50 条，验证新标签、tokenizer、显存与保存链路。正式训练开始时还会全量加载混合 SFT。

## 正式对照训练

在前述 tmux 会话中继续运行；如换了 shell，先将 `ROUND2` 手动设置为刚才实际输出的目录。由本地底座重新训练新 LoRA，不从旧 epoch-3 adapter 续训；保持第一轮 `epochs=3 / batch=8 / gradient_accumulation=4 / max_seq_length=2048 / lr=2e-4 / seed=42 / memory_fraction=0.17`。权重仍写入项目的 `data/model_output/`。

```bash
cd ~/kube-user/CodeBase_YangJunjie/Mova_AI/scene_ai_server
BASE_MODEL="$HOME/kube-user/CodeBase_YangJunjie/models/Qwen3-0.6B"
RUN_ID="$(date +%Y%m%d_%H%M%S)"
RUN_OUT="data/model_output/qwen3-0.6b-round2-${RUN_ID}"
mkdir -p data/train_logs
python3 train_lora.py \
  --base-model "$BASE_MODEL" \
  --train-file "$ROUND2/sft_train.jsonl" \
  --epochs 3 \
  --per-device-batch-size 8 \
  --gradient-accumulation-steps 4 \
  --max-seq-length 2048 \
  --learning-rate 2e-4 \
  --seed 42 \
  --memory-fraction 0.17 \
  --output-dir "$RUN_OUT" \
  2>&1 | tee "data/train_logs/round2-${RUN_ID}.log"
test "${PIPESTATUS[0]}" -eq 0 || { echo '正式训练失败'; exit 1; }
```

训练前确保当前 GPU 的实际空闲显存至少 40 GiB，且分配给本任务的配额仍为 40 GiB。预计新训练集约 5704 条，实际数字以 `manifest.json` 为准。训练完成后以第一轮 epoch-3 对照第二轮各 epoch 在旧 500 条和锁定 150 条上的表现，并单列 `need_cloud=true` 召回和具体地点映射；0.95 一类固定置信度不能当作已校准概率。
