# 150 条独立定向测试：结果与下一轮修复方向

> 核查日期：2026-10-08。这里的探针由 AI 起草并复核，未用教师 API 标注；它是新话语压力测试，**不是人工标注金标准，也不代表真实流量分布**。本轮只比较现有 epoch-2/3，未重训模型。

## 数据与复算边界

- `gold_v1.jsonl`：150 条、20 种环境信号，SHA-256 `b0d292fd189421d6e762b979540481ca5fb333d4ad585fe335682fa902324fa4`；manifest 标记 `reviewer=ai`。
- 与正式 5500 条训练源、500 条旧评测集：完全重复 0 条，三字片 Jaccard ≥0.78 的近重复 0 条。训练与旧评测 MD5 分别是 `d32b73adbc456212f42eaae2099d93ee`、`27a33ffbf5d2dd01d391533cb0443f3c`。
- 两轮各 150 条预测，ID 与 gold 完全一致；本地用 `tools/independent_eval.py score` 复算的 `report.json` 与服务器下载报告一致。原始 gold、预测和错误清单保留在忽略提交的 `scene_ai_server/data/independent_eval/`，不上传公开仓库。
- `need_cloud` 只标注 50 条（`true` 35 条、`false` 15 条）；槽位只检查已标注的 `place_type` 与 `relation`，没有用猜测值给其他槽位打分。

## 错误集中在哪里

1. **当前位置枚举映射**：epoch-3 的 `place_type` 为 36/53。预期为“其他”的 20 条全部正确；预期为具体枚举的 33 条只有 16 条正确，其余 17 条均被判为“其他”。典型表述包括火锅店/面馆/食堂 → 餐厅、候车厅/地铁站 → 交通枢纽、教学楼/学校宿舍 → 校园，以及商业综合体 → 商场。`location_destination` 的 5/15 全字段通过率说明显式当前位置与目的地同现时尤其容易失败。
2. **上云判断偏向 false**：epoch-3 对本地提醒的 15 条 `false` 全对，但对 35 条 `true` 仅答对 18 条。明确要求附近场所**当前营业或开放信息**的 15 条全部输出 `false`；饮食建议另有 2 条误判为 `false`。这类任务需要外部实时信息，现有模型路由不能直接用于生产放行。
3. **食物边界**：`food_boundary` 有 4/15 条把新鲜度、成熟度或挑选问题错路由到 `food`；`food_diet` 有 4/10 条把以控糖、增肌或清淡饮食为核心的问题判为 `recipe_lookup`。两轮的这 8 条错误完全相同。
4. **聊天关系与意图**：epoch-3 为 26/30。表妹被判为朋友、外卖员回复被判为无场景是较明确的错误；“帮我回得自然一点”等表达横跨 `reply_suggest` 与 `tone_adjust`，AI 复核标签仍可能有歧义，若要作为人工金标准须重新审定。
5. **置信度未校准**：epoch-3 的 150 条输出 `confidence` 全为 0.95，包含全部 40 条错误样本。它无法区分本轮对错，不能用 0.95 直接设置端云路由阈值。

## 模型选择与下一轮动作

在这份压力测试上，**epoch-3 是下一轮修复和端侧性能测试的基线候选**：整体全对数、scene、intent、已标注槽位均优于 epoch-2；`need_cloud` 则比 epoch-2 少对 1 条。差异只有 5/150，且样本是 AI 起草、刻意偏向已知边界，不能据此宣称 epoch-3 普遍更优。两轮均未达到多个关键问题族的预设门槛，当前不作质量放行。

1. **冻结本轮 gold**：保留 `gold_v1.jsonl` 与 manifest，不把这 150 条话语或其预测反馈直接混入训练。若发现含糊标签，记录问题并另建版本与新测试集，不回填本轮成绩。
2. **审计正式 5500 条训练标签**：统计具体位置同义词、当前位置/目的地并存、实时营业信息与饮食管理请求的数量及教师标签。先排查覆盖不足或相互矛盾，再判断是否修改契约或提示词；目前本地没有完整训练源，不能把“模型容量不足”当成已证实原因。
3. **补新的对照样本**：围绕位置枚举、实时信息上云、食物新鲜度与饮食管理收集不同表述，分开记录训练新增样本和留出的新测试样本。为关键边界取得人工审定标签；不要复用本轮 150 条当作新模型的独立测试成绩。
4. **对照重训与端侧验证**：固定底座、训练设置和评测口径，比较原模型与增量数据模型；另用新的留出集判定改进是否成立。现有 epoch-3 可同时用于 LoRA 合并、量化和手机推理耗时/内存冒烟，但质量问题解决前不作为最终部署权重。

此前 500 条教师标签评测中的高分与本轮结果不能直接相减解释为真实场景准确率下降：标签来源、场景配比、上云字段覆盖和压力测试选题均不同。两个结果合在一起说明：模型能稳定复现已见契约格式，但关键边界仍需新的数据和人工验证。
