# 公司服务器操作快速上手

适用对象：需要在本公司 GPU 服务器上训练/推理/传文件的同事
编写日期：2026-09-03

---

## 1. 服务器是什么环境

- **操作系统**：Linux（命令行环境，没有图形界面，全部靠命令操作）
- **登录身份**：root（容器/节点名：`xxx`）
- **GPU**：**NVIDIA B200**，单卡显存 **182624 MiB（约 178 GB）**
- **软件环境**：Python 3.13.2（miniconda3）、PyTorch 2.13.0+cu130、Ultralytics 8.4.115

### GPU 是共享的，务必先看占用

其他人/任务可能正在使用同一张卡（例如 vLLM 推理服务约占 76 GB、RL 训练约占 49 GB），**实际可用显存约 50 至 55 GB**。开始训练前先执行：

```bash
nvidia-smi
```

查看显存占用（Memory-Usage 一列）和当前运行的进程（Processes 一段）。

### 硬件信息自查命令

| 查看内容 | 命令 |
| --- | --- |
| GPU 型号与显存占用 | `nvidia-smi` |
| CPU 核数 | `lscpu` |
| 内存总量/剩余 | `free -h` |
| 磁盘剩余空间 | `df -h` |
| 当前目录 | `pwd` |

## 2. 怎么连服务器

### 方式一：终端（SSH）

用 Xshell、MobaXterm、Windows 自带终端或 VS Code 的 Remote-SSH 连接，输入服务器 IP、端口、用户名密码后即可进入命令行。

### 方式二：WinSCP（传文件）

WinSCP 用于把本地文件上传到服务器、或把服务器结果下载到本地，界面分左右两栏：左边是本机 Windows，右边是服务器 Linux。

## 3. 目录（文件夹）操作

### 3.1 看自己在哪、有哪些文件

```bash
pwd              # 显示当前所在目录的完整路径
ls               # 列出当前目录下的文件与文件夹
ls -la           # 列出全部（含隐藏文件）+ 详细信息（权限、大小、时间）
ls -lh           # 文件大小以 K/M/G 显示，便于阅读
```

### 3.2 进入某个文件夹

```bash
cd 目录名                 # 进入当前目录下的某个子文件夹
cd /root/kube-user        # 用绝对路径进入（以 / 开头 = 从根目录算起，任何位置都能用）
```

### 3.3 从一个文件夹切换到另一个

| 目的 | 命令 |
| --- | --- |
| 进入子文件夹 | `cd 子文件夹名` |
| 返回上一级 | `cd ..` |
| 回到自己的主目录 | `cd ~` 或直接 `cd` |
| 回到上一次所在的目录 | `cd -` |
| 跳到任意位置 | `cd /完整/绝对/路径` |
| 路径含空格或中文 | 用引号包住，如 `cd "data/长航对内建筑物"` |

**小技巧**：输入路径时按 **Tab 键**可自动补全，避免打字出错；连按两次 Tab 会列出所有候选。

### 3.4 常用文件操作

```bash
mkdir 新文件夹名                 # 新建文件夹
cp 源文件 目标路径               # 复制文件（复制文件夹加 -r）
mv 源文件 目标路径               # 移动或重命名
rm 文件名                        # 删除文件
rm -rf 文件夹名                  # 删除文件夹（危险，不可恢复，慎用）
cat 文件名                       # 查看小文件全部内容
tail -f 日志文件                 # 实时滚动查看日志（Ctrl+C 退出）
find . -name "*.pt"              # 在当前目录及子目录查找 .pt 文件
```

## 4. WinSCP 与训练容器的路径、权限排查

WinSCP 连接的 SSH 主机和训练容器可能通过挂载目录共享文件。两边显示的绝对路径不一定相同，登录账号和容器账号也可能不同；不要仅凭路径字符串或容器内的 `id` 推断 WinSCP 的权限。

### 4.1 先确认两边看到的是不是同一份目录

- 训练容器里用 `pwd`、`readlink -f 目录` 和 `ls -ld 目录` 查看实际路径与目录属性；
- WinSCP 右侧地址栏显示的是 SFTP 主机视角的路径。容器挂载路径和主机路径可能不同；
- 若一边创建目录后另一边能看到它，说明目录可能由挂载共享，但仍要核对目录属主、权限和实际文件。

### 4.2 对应关系与统一方法

1. **在训练容器里检查目标目录**：
   ```bash
   MODEL_DIR="/path/to/model"
   readlink -f "$MODEL_DIR"
   ls -ldn "$MODEL_DIR"
   stat -c 'owner=%u:%g mode=%A path=%n' "$MODEL_DIR"
   ```
2. **在 WinSCP 登录账号的 SSH 终端里查身份**：WinSCP 菜单“命令 → 打开终端”（`Shift+Ctrl+T`），或“命令 → 在 PuTTY 中打开”（`Ctrl+P`），执行：
   ```bash
   id -u
   id -g
   ```
   注意：在 root 训练容器里运行 `id` 得到的是 root 的 UID/GID，并不代表 SFTP 登录账号。
3. 只有确认训练容器路径与 WinSCP 路径指向同一挂载目录后，才根据 SFTP 账号查到的数字 UID/GID 调整属主；调整后再次用 `stat` 检查，并在 WinSCP 刷新目录验证可写。

### 4.3 常见权限错误

- 由 root 在共享目录里创建的目录通常归 root 所有。若 WinSCP 使用另一个账号上传，可能报 `Permission denied`，并提示无法创建 `*.filepart` 临时文件；
- 在训练容器的 root shell 中用数字 UID/GID 修正属主时，先从 WinSCP 对应的 SSH 会话查询 UID/GID，并核实目标路径是同一个挂载目录。不要把 root shell 的 `0:0` 当作 SFTP 账号身份；
- 如果 `chown` 报 `Operation not permitted`，共享存储可能限制了容器改属主。改用 SFTP 账号可写的目录，或联系存储管理员调整权限；不要对共享目录使用 `chmod 777`；
- 上传文件时**确认 WinSCP 右侧当前目录**是预期位置；大文件传输失败后，确认任务已停止再检查残留的临时文件；
- 文件名含**中文或空格**时，命令行里要用引号包住；
- WinSCP 建议使用**二进制模式**传输（大文件更稳，避免换行符被改动）；
- 若终端里 `ls` 看不到刚上传的文件，分别检查两端路径、挂载关系和文件属主，不要假设绝对路径相同。

### 4.4 实战记录：模型权重上传时报权限拒绝（2026-09）

- **现象**：WinSCP 上传模型权重时，无法创建 `.filepart` 临时文件，返回 `Permission denied`。
- **原因**：训练容器用 root 创建了目标目录，目录属主为 `0:0`；WinSCP 使用的 SFTP 账号 UID/GID 为另一组值。此前在 root shell 执行 `id` 只查到了容器 root，不能用于判断 SFTP 账号权限。WinSCP 主机路径与容器内挂载路径也不是同一条路径字符串。
- **处理**：从 WinSCP 对应的 SSH 会话查询 SFTP 账号 UID/GID；在确认容器目标目录映射到同一挂载目录后，将该目录属主改为相应数字 UID/GID；用 `stat` 验证属主，再刷新 WinSCP 重试上传。
- **隐私处理**：主机地址、账号、密码、节点标识和个人目录均以 `xxx` 表示；实际 UID/GID 以部署环境查询结果为准，不写死在文档中。

## 5. Python 虚拟环境

### 5.1 查看服务器上有哪些环境

```bash
conda env list          # 列出所有 conda 环境（当前激活的会用 * 标出）
conda info --envs       # 同上
```

常见输出形如：

```
# conda environments:
#
base                  *  /root/miniconda3
其他环境名                 /root/miniconda3/envs/其他环境名
```

### 5.2 激活与退出

```bash
conda activate 环境名      # 激活指定环境
conda activate             # 或 source activate 环境名
conda deactivate           # 退出当前环境，回到上一层
```

激活成功后，命令提示符最前面会出现 `(环境名)`，例如 `(base) root@...`。

### 5.3 确认环境里的软件

```bash
which python                   # 当前使用的是哪个 python
python --version               # Python 版本
pip list | grep ultralytics    # 是否装了 ultralytics
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

最后一条能输出 torch 版本且 `True`，说明 GPU 可用。

### 5.4 如果某个环境里缺包

```bash
conda activate 目标环境
pip install 包名                # 例如 pip install ultralytics
```

## 7. 长时间任务：用 tmux 挂后台

训练一跑就是几小时，**直接跑一旦断网就中断**。建议用 tmux：

```bash
tmux new -s train        # 新建名为 train 的会话
# 在会话里正常执行训练命令
# 按 Ctrl+B 松开再按 D  → 退出会话（任务继续在后台跑）
tmux ls                  # 查看所有会话
tmux attach -t train     # 重新回到该会话
```

## 8. 安全提醒

1. **`rm -rf` 不可恢复**：执行前先 `ls` 确认路径，尤其不要在有训练成果的目录里误删；
2. **GPU 是共享的**：跑大任务前先 `nvidia-smi` 看占用，避免和别人抢显存导致双方失败；
3. **重要结果及时下载**：训练权重、评测结果建议及时用 WinSCP 拉回本地备份；
4. **不要随意改动他人目录**：只操作自己项目目录下的文件。
5. **不要把凭据或内部地址提交到公开仓库**：密码、访问令牌、真实服务器 IP、主机标识和个人目录应从文档与配置示例中移除或替换为 `xxx`；本地凭据放在未提交的环境变量或密钥管理工具中。
